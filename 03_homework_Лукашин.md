## 1. Что такое контроль конфигурации

Контроль конфигурации (configuration management, CM) — это дисциплина управления
изменениями: она фиксирует, из каких компонентов состоит система в каждый момент
времени, кто и зачем их изменил, и позволяет вернуться к любому предыдущему
состоянию. Без контроля конфигурации невозможно ответить на вопросы «что именно
работает на сервере» и «какая версия кода у заказчика».

Основные задачи: идентификация конфигурации (что считать элементом), контроль
изменений, учёт состояния и аудит конфигурации.

## 2. Инструменты контроля конфигурации

### 2.1. Git

Распределённая система контроля версий. Каждый разработчик хранит полную историю
проекта локально, а обмен изменениями идёт через удалённый репозиторий.

Применение в проекте «Программа складского учёта»:

```bash
git init
git add .
git commit -m "feat: справочник users"
git checkout -b feature/reports
git push origin feature/reports
```

Правила, которых придерживается команда: отдельная ветка на задачу, обязательный
code review через pull request, запрет прямых коммитов в `main`, осмысленные
сообщения коммитов по соглашению Conventional Commits.

### 2.2. Ansible

Инструмент управления конфигурацией серверов (infrastructure as code). Описывает
желаемое состояние в YAML-плейбуках, что делает настройку сервера воспроизводимой.

```yaml
- name: Настройка сервера приложения
  hosts: app
  become: yes
  tasks:
    - name: Установить PostgreSQL
      apt: name=postgresql state=present
    - name: Создать каталог проекта
      file: path=/srv/lukashin_app state=directory owner=www-data
```

### 2.3. Docker

Контейнеризация фиксирует не только код, но и окружение: версии Python,
библиотек и системных пакетов. `Dockerfile` и `docker-compose.yml` — это тоже
элементы конфигурации, которые хранятся в Git.

### 2.4. Сравнение инструментов

| Инструмент | Что контролирует | Уровень |
|---|---|---|
| Git | исходный код, документацию, конфигурационные файлы | приложение |
| Ansible | состояние серверов, установленные пакеты, сервисы | инфраструктура |
| Docker | образы и окружение приложения | среда исполнения |

## 3. Стандарт ISO/IEC/IEEE 12207

Стандарт описывает процессы жизненного цикла программных систем. Для нашего
проекта значимы процессы:

- **Технические процессы:** анализ требований, проектирование, реализация,
  тестирование, ввод в эксплуатацию.
- **Процессы поддержки:** управление конфигурацией, обеспечение качества,
  верификация и валидация, документирование.
- **Организационные процессы:** управление проектом, управление рисками.

Практическое следствие: у каждого этапа должен быть вход, выход и критерий
готовности. Например, этап «Тестирование» завершается отчётом с перечнем
проверенных сценариев и отсутствием критичных дефектов.

## 4. Стандарт ISO 9001

Стандарт системы менеджмента качества. Ключевые принципы, применимые к
разработке ПО: ориентация на потребителя, процессный подход, постоянное
улучшение, принятие решений на основе данных.

В проекте «Программа складского учёта» это выражается в следующем:

1. Требования фиксируются и согласуются с заказчиком до начала разработки.
2. Каждое изменение проходит проверку (тест или code review).
3. Дефекты регистрируются, анализируются причины и принимаются меры.
4. Регулярно собираются метрики: число дефектов, время исправления, доля
   пройденных тестов.

## 5. Вывод

Контроль конфигурации — не бюрократия, а способ сделать разработку
предсказуемой: Git фиксирует историю кода, Ansible и Docker — состояние
инфраструктуры, а стандарты ISO/IEC/IEEE 12207 и ISO 9001 задают рамку
процессов и критерии качества. Внедрение этих практик снижает риск потерять
изменения и упрощает передачу проекта другому разработчику.
